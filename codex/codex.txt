Some rules about documenting progress and versioning:

Let's say today we're at version 0.2.7, meaning I had said "bump version to 0.2.7" at some point, and I'll get to that.

All features or stuff that went into 0.2.7 (and prior version) are documented in CHANGELOG, which is a summarized/condensed version of the 0.2.7 section in VERSION_HISTORY, which contains minor and major changes for features and bug fixes, so basically a lot of detail.

VERSION_PLAN is updated when I want to keep a record of things I want to add to Skannr, and is more losely organized wrt versioning b/c/ I might say "let's do XYZ in 0.3" or so.

So when I want the version to be bumped up to let's say 0.2.8, we do the following:
- update VERSION
- summarize/condense the post-0.2.7 stuff from VERSION_HISTORY and add a 0.2.8 section in CHANGELOG
- create a new 'post-0.2.8 section' in VERSION_HISTORY that will house the stuff we do after the 0.2.8 release.

Generally, when making changes that affect content in README.md and/or DESIGN.md, then make the approproate changes. Occasionally, review code + docs that they match. Update VERSION_HISTORY with the changes we do anytime.

We also have scripts/skannr_regression_test.py and scripts/skannr_admin.py . It's only run outside Codex !
